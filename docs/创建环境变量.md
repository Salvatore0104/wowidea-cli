# 自己创建环境变量 WOWIDEA_API_KEY

安装脚本在没检测到 `WOWIDEA_API_KEY` 时会弹出窗口（没有图形界面则在终端里隐藏输入）。你也可以按本文自己建这个变量。变量名必须是全大写的 `WOWIDEA_API_KEY`，一个字母都不能差。

## 先拿到密钥

1. 用浏览器打开 [https://wowidea.top/user/api-key](https://wowidea.top/user/api-key)。地址栏应停在 `wowidea.top`，路径是 `/user/api-key`。
2. 没登录就先登录。登录后页面上能看到已有密钥，或一个用来新建密钥的按钮。
3. 新建一把密钥。复制整段内容，一般以 `sk-` 开头。复制时不要多带空格、引号或换行。
4. 先把密钥放进系统剪贴板，立刻按下面某一节写进环境变量。不要先贴到聊天、邮件、备忘录或仓库文件里中转。
5. 页面上如果还能看到这把密钥，用完就关掉标签页。丢了就在同一页再新建一把，并把旧的作废。

## 不要做的事

- 不要把密钥提交进 Git。不要写进仓库里的 `.env`、README、`AGENTS.md`、技能文件、提交说明、PR 或 issue。
- 不要把密钥贴进聊天，包括发给助手的那句话。助手需要时，只在本机环境变量里放。
- 不要截图、录屏时露出密钥。
- 不要把密钥写在会进入 shell 历史的命令里（例如直接 `export WOWIDEA_API_KEY=sk-...` 再回车）。下面用编辑器改启动文件，或用安装脚本的隐藏输入。

## macOS（终端）

macOS 自带的「终端」和 iTerm 从 Catalina 起默认是 zsh，对应文件是 `~/.zshrc`。只有你自己把默认 shell 改成 bash 时，才改 `~/.bashrc`（登录壳还要看 `~/.bash_profile`）。

1. 按 `Command + 空格` 打开 Spotlight，输入 `终端` 或 `Terminal`，回车。窗口标题是「终端」。
2. 看当前是哪种 shell：

```bash
echo "$SHELL"
```

结果以 `/bin/zsh` 结尾就用下一节的 `~/.zshrc`。以 `/bin/bash` 结尾就用再下一节。

### zsh：写入 ~/.zshrc

1. 在终端输入下面这行并回车。没有这个文件时，nano 会新建：

```bash
nano ~/.zshrc
```

2. 用方向键移到文件最后一行下面。空一行，再输入（把引号里的内容换成你复制的密钥，引号保留）：

```bash
export WOWIDEA_API_KEY="sk-这里粘贴密钥"
```

这一行必须单独成行，行首不要有空格以外的符号，不要写成智能引号 `“ ”`。等号两边不要加空格。

3. 保存并退出 nano：按 `Control + O`，再按回车确认文件名，然后按 `Control + X`。
4. 让当前窗口读到新内容：

```bash
source ~/.zshrc
```

5. 核对变量已经进了这个窗口。下面这条会把密钥打在屏幕上，只在你自己的电脑上做，做完执行 `clear`：

```bash
echo "$WOWIDEA_API_KEY"
```

应看到以 `sk-` 开头的整段密钥。如果是空的，回到 nano 检查有没有写错变量名、有没有漏掉 `export`，保存后再 `source ~/.zshrc` 一次。

6. 关掉这个终端窗口，再打开一个新窗口，再执行一次 `echo "$WOWIDEA_API_KEY"`。新窗口也能看到，说明以后不用每次手动 `source`。

不想用 nano 时：先 `touch ~/.zshrc`，再 `open -e ~/.zshrc` 用文本编辑打开。如果菜单「格式」里有「制作纯文本」，先点它，避免存成 RTF。把上面那行 `export` 加在文件末尾，按 `Command + S` 保存，回到终端执行 `source ~/.zshrc`。

### bash：写入 ~/.bashrc

1. `echo "$SHELL"` 以 `/bin/bash` 结尾时，编辑 bash 的启动文件：

```bash
nano ~/.bashrc
```

2. 在文件末尾加上同一行：

```bash
export WOWIDEA_API_KEY="sk-这里粘贴密钥"
```

3. `Control + O`、回车、`Control + X` 保存退出。
4. 当前窗口执行：

```bash
source ~/.bashrc
echo "$WOWIDEA_API_KEY"
```

5. macOS 上，bash 作为登录壳时读的是 `~/.bash_profile`，不读 `~/.bashrc`。新开的终端窗口如果 `echo` 是空的，用 nano 打开 `~/.bash_profile`，在末尾加上：

```bash
[ -f ~/.bashrc ] && . ~/.bashrc
```

保存后再开一个终端窗口核对。不要为了密钥去新建一个空的 `~/.bash_profile` 来挡住 `~/.profile`；只有这个文件已经存在时才改它。

安装脚本如果已经写过，文件里会有一行注释 `# wowidea-cli: WOWIDEA_API_KEY (managed by scripts/install.sh)`。看到它就不要再加第二行 `export`。

## Linux（终端）

Ubuntu、Debian 桌面默认是 bash，文件是 `~/.bashrc`。Fedora、Arch 也多半是 bash；如果 `echo "$SHELL"` 以 `zsh` 结尾，就改 `~/.zshrc`，步骤和 macOS 的 zsh 相同。

1. 打开终端。Ubuntu 上按 `Ctrl + Alt + T`。窗口里应有命令提示符，例如 `用户名@电脑名:~$`。
2. 确认 shell：

```bash
echo "$SHELL"
```

3. bash 执行：

```bash
nano ~/.bashrc
```

zsh 执行 `nano ~/.zshrc`。

4. 移到文件末尾，空一行，加上：

```bash
export WOWIDEA_API_KEY="sk-这里粘贴密钥"
```

5. `Control + O`、回车、`Control + X`。
6. 当前窗口立刻生效：

```bash
source ~/.bashrc
echo "$WOWIDEA_API_KEY"
```

zsh 则是 `source ~/.zshrc`。`echo` 会把密钥打在屏幕上，只在你自己的电脑上做，然后执行 `clear`。

7. 关掉终端再打开一个。再 `echo "$WOWIDEA_API_KEY"`。还是空的话，看是不是登录壳没读 `~/.bashrc`。打开 `~/.profile`，如果里面没有下面这一行，就加上（Ubuntu 默认通常已经有）：

```bash
[ -f ~/.bashrc ] && . ~/.bashrc
```

改的是你自己的主目录，不要用 `sudo` 去改 root 的文件。跑 `wowidea` 的是哪个用户，变量就写在那个用户的启动文件里。

安装脚本写过的标记同样是 `# wowidea-cli: WOWIDEA_API_KEY (managed by scripts/install.sh)`。有这行就不要再加一条。

## Windows 11 和 Windows 10（图形界面）

图形界面写的是「用户变量」，新开的窗口都能读到，也不会把密钥留在 PowerShell 历史里。优先用这一节。

### 两条路都可以打开同一个窗口

**搜索（Windows 11，以及较新的 Windows 10）：**

1. 点任务栏上的 Windows 图标，或按键盘上的 Windows 键。
2. 直接输入 `环境变量`（不要先点到别的搜索分类）。
3. 在结果里点「编辑账户的环境变量」。标题栏应是「环境变量」，上半部分是当前用户的变量。
4. 如果只看到「编辑系统环境变量」，点它会先打开「系统属性」。接着走下面的经典路径，从第 4 步继续。

**经典路径（Windows 10 和 Windows 11 相同）：**

1. 按 `Windows + R`，出现「运行」。
2. 输入 `sysdm.cpl`，点「确定」。打开的窗口标题是「系统属性」。
3. 点上方的「高级」选项卡。
4. 右下角点「环境变量(N)...」。
5. 新窗口分成上下两块。上块标题类似「用户变量」，名字是你的 Windows 用户名。下块是「系统变量」，对这台电脑上所有用户生效。密钥只放上块。

### 新建变量

1. 在上块「用户变量」下面点「新建(N)...」。不要点下块的新建。
2. 「变量名」一栏输入 `WOWIDEA_API_KEY`。全大写，中间是下划线。不要加 `export`，不要加引号。
3. 「变量值」一栏粘贴密钥本身，例如 `sk-` 开头的那一整段。不要加引号，首尾不要空格。
4. 点「确定」。回到环境变量窗口后，上块列表里应出现一行：名称是 `WOWIDEA_API_KEY`，值是你的密钥。
5. 再点「确定」关掉环境变量窗口。如果是从「系统属性」进来的，再点一次「确定」把它也关掉。
6. 已经开着的 PowerShell、终端、Cursor 都还是旧环境。把它们关掉，重新打开一个窗口。只关标签不行的话，退出整个终端应用再开。

### 在新窗口里核对

PowerShell：

```powershell
echo $env:WOWIDEA_API_KEY
```

命令提示符（cmd）：

```bat
echo %WOWIDEA_API_KEY%
```

应打出密钥。打出来是 `%WOWIDEA_API_KEY%` 原文，或是空的，说明还在旧窗口里，或变量名写错了，或点成了系统变量。回到环境变量窗口看上块列表。核对后关掉这个窗口，或执行 `cls`，避免密钥留在屏幕上。

## Windows（PowerShell：当前窗口和 setx）

图形界面和 `setx` 二选一即可，不要配完图形界面又 `setx` 一遍。

当前窗口临时生效（关掉窗口就没了）：

```powershell
$env:WOWIDEA_API_KEY = "sk-这里粘贴密钥"
echo $env:WOWIDEA_API_KEY
```

写入用户环境、以后新窗口都有效：

```powershell
setx WOWIDEA_API_KEY "sk-这里粘贴密钥"
```

成功时 setx 会打印 `SUCCESS: Specified value was saved.`。这条命令不会改已经打开的窗口。紧接着在同一窗口再执行一次 `$env:WOWIDEA_API_KEY = "sk-..."`，当前窗口才能用；然后新开一个 PowerShell，只跑 `echo $env:WOWIDEA_API_KEY` 做核对。

`setx` 会把整条命令留在 PowerShell 历史里（PSReadLine 的历史文件）。密钥里如果有 `%` 或英文双引号，setx 还可能改坏或截断。遇到这两种情况，改用上面的图形界面。用过 `setx` 之后，打开历史文件，删掉含密钥的那一行：

```powershell
notepad (Get-PSReadLineOption).HistorySavePath
```

## 验证

变量在当前窗口里能被 `echo` 看到之后，再跑：

```bash
wowidea balance
```

PowerShell 里是同一条命令。退出码 0 表示这把密钥可用，输出里有余额。退出码 3 表示进程里没有这把密钥，或密钥被拒绝。先在同一个窗口 `echo` 变量，确认不是空的，再核对 [API Key 页](https://wowidea.top/user/api-key) 上的密钥是否还有效。不要把 `echo` 或 `wowidea balance` 的输出贴到聊天里。

`wowidea` 提示找不到命令时，先新开一个终端。还是没有，再看安装脚本打印的「已安装：」后面的路径。
